Keep The Page

Keeps publisher anti-adblock and consent-or-pay walls from hiding article pages.

Protections

All on by default. Turning one off writes data-ktp-off to the page so the in-page guards can see it — with everything on, the extension writes nothing to the page at all.

Tracing

Off by default, and off means silent: with tracing disabled the extension writes no marker to the page at all. Turning it on sets an attribute on <html> so the in-page guards can see which channels are active — which a site could in principle detect. Fine for debugging, worth turning back off afterwards.

What to trace

Logging only — these do not turn any protection on or off. The switches are in Protections above, and the names match one for one.

MSN and Bing feeds

Both run the same widget stack, so one set of switches covers them. MSN's own Content settings cannot do this job: those are stored on Microsoft's servers against your anonymous MUID rather than in a cookie, switching Comments off there leaves the comment links in place, and none of it reaches bing.com at all.

You will often see the MSN feed before it goes. MSN sends its cards inside the page itself and paints them early, and no extension code — stylesheet or script — reliably beats that on every load. What these switches guarantee is the end state, not a clean one: the content is removed, and on Bing the feed data is never fetched at all. If the flash matters more to you than the feed, MSN is better left on its own Personalise → Content settings, which takes effect server-side before the page is built.

Errors

Nothing reported. The guards swallow their own exceptions so they can never break a page — anything they swallow lands here.
